# کمینه/بیشینه و شاخص‌های تخصصی مقصد

این تغییر ابتدا روی `stage`، پس از fast-forward به `main` در `ba32388` آماده
شده است. مقصد، مسیر، URL، canonical، GA، font و تصاویر اصلی تغییر نکرده‌اند.
نه endpoint تازه داریم، نه migration، نه دریافت provider در GET یا مرورگر.

## قرارداد همان API هفته

| فیلد interval | معنا |
| --- | --- |
| `felt_min` / `felt_max` | کمینه/بیشینهٔ دمای حسی ساعتی همان بازه |
| `min` / `max` | کمینه/بیشینهٔ دمای واقعی، بدون تغییر نام یا معنا |
| `uv_index` | بیشینهٔ UV ساعت‌های همان بازه؛ صفر معتبر است |
| `heat_index_c` | بیشینهٔ شاخص گرمای ساعت‌های قابل‌محاسبهٔ همان بازه |
| `heat_index_status` | `available`، `not_applicable` یا `missing` |

دمای حسی/واقعی، UV و گرما از پنجرهٔ نیمه‌باز `[from,to)` تهران می‌آیند؛ بارش
همان پنجرهٔ قبلی `(from,to]` را دارد. پوشش کامل ساعت‌ها و اعتبار هر فیلد جدا
بررسی می‌شود. نبود بارش، دمای معتبر را حذف نمی‌کند. UV منفی/ناموجود، null است.

شاخص گرما از همان موتور `hazards.assessment`، فرمول و ورودی‌های هم‌زمان دما و
رطوبت مصرف می‌شود؛ ارزیابی ساعتی پیش از تجمیع یک‌بار انجام می‌شود. اگر ورودی
حتی یک ساعت لازم ناقص/نامعتبر باشد، بیشینهٔ قطعی تولید نمی‌شود (`missing`).
اگر ورودی کامل باشد اما هیچ ساعت در دامنهٔ گرم فرمول نباشد، `not_applicable`
است. ساعت خنک در کنار ساعت گرم، ساعت ناموجود نیست. apparent temperature هرگز
جایگزین شاخص گرما نمی‌شود. خوانش‌های برنامهٔ مسیر نیز مقدار/وضعیت گرما را از
همین موتور دریافت می‌کنند، ولی ظاهر مسیر/عکس اشتراک تغییر نکرده است.

گرما با یک رقم اعشار گزارش می‌شود؛ فقط اگر گردکردن مقدار زیر مرز ۳۲ یا ۴۰
را به خود مرز برساند، دهمِ پایین مرز گزارش می‌شود (۳۹٫۹۶ → ۳۹٫۹). بنابراین
عددِ ۴۰ بدون هشدار قرمز ناشی از گردکردن ساخته نمی‌شود. قاعدهٔ خطر همچنان روی
مقدار محاسبه‌شدهٔ اصلی است و آستانه‌های قبلی تغییر نکرده‌اند.

## نمایش

- جفت عدد فارسی با جهت LTR و علامت درجه: `min°/max°`؛ بدون متن راهنمای اضافه.
  معنای کمینه/بیشینه در برچسب دسترس‌پذیر باقی است. روز کل ۲۴ ساعت، ۶/۳ساعته
  همان بازه، و ۱ساعته فقط خوانش منحنی را نمایش می‌دهد. در حالت ترکیبی، ارتفاع
  جایگاه جفت عدد محفوظ است. دامنه و هندسهٔ منحنی‌های قبلی حفظ شده‌اند.
- ردیف UV پیش‌آخر: پنج نقطهٔ کوچک با طبقه‌های ثابت زیر۳، ۳–۵، ۶–۷، ۸–۱۰ و
  ۱۱ به بالا. صفر هیچ نقطهٔ پررنگ ندارد. این‌ها طبقهٔ بصری‌اند، نه سیاست خطر
  تازه. UV به مثلث روز یا رنگ سایر داده‌ها هشدار جدید اضافه نمی‌کند.
- ردیف گرما آخر: ستونک باریک با مقیاس ثابت `7 + (HI - 32) × 1.5` پیکسل، محدود
  به ۳ تا ۴۳ پیکسل؛ عدد بیرون از مقیاس نیز کامل نمایش دارد. رنگ قرمز فقط از
  هشدار critical مشترک همان بازه می‌آید، نه محاسبهٔ موازی در فرانت.
- دو وضعیت بدون مقدار با «—» دیده می‌شوند، اما title/برچسب علتِ نبود داده را
  از خارج‌بودن شرایط از دامنهٔ کاربرد تفکیک می‌کند. گرما برآورد در سایه است.
- ردیف‌های باد، بارش، تندباد، جهت، رطوبت، دید و تراز صفر درجه بدون تغییرند؛
  آیکون/خط پیوستهٔ جدید، تغییر فونت یا زبان بصری تازه اضافه نشده است.

## کش و انتشار

نسخهٔ Redis payload برابر `week-9` است؛ ETag از بدنهٔ تازه ساخته می‌شود.
نخستین GET هفته در bootstrap و client یکسان `cache: no-cache` است: کش خصوصی
مرورگر revalidate می‌شود، بدون درخواست دوم یا retry. حافظهٔ سه‌صفحه‌ای دو
دقیقه‌ای و سیاست private/CDN no-store دست‌نخورده‌اند. کنترل‌ها درخواست هوا
ندارند. تغییر بکند و فرانت با انتشار عادی همان نسخه اعمال شود.

برای دیپلوی استیج از لوکال:

```bash
cd /home/nobitex/Desktop/Tasks/Nobitex/hawatch-stage
bash scripts/deploy-stage-hawatch
```

سپس `http://202.133.89.120:5050/points/tochal` را باز کنید؛ UV/گرما در «جزئیات
تخصصی» هستند. مقدار گرما برای روز خنک عمداً «—» است. راهنمای جداسازی سرویس‌ها،
DB و noindex در [stage-deployment.md](stage-deployment.md) است.

## بررسی

تصاویر واقعی مرورگر و گزارش ۱۶ ترکیب در
[design/screens/forecast-indicators](../design/screens/forecast-indicators/README.md)
هستند. دادهٔ این تصاویر synthetic و فقط در دیتابیس موقت محلی است؛ گرمای آن‌ها
ادعای هوای واقعی توچال نیست. به production یا دیتابیس استیج چیزی نوشته نشده است.

مقایسهٔ سه اجرای محلی `build_week` با DB و دادهٔ یکسان:

| بسته | query مین/جدید | JSON مین/جدید (byte) | gzip مین/جدید (byte) | میانهٔ ساخت مین/جدید (ms) |
| --- | --- | --- | --- | --- |
| مقصد | ۹ / ۹ | 329870 / 359334 | 14895 / 15700 | 433.5 / 442.2 |
| مسیر | ۱۶ / ۱۶ | 1247100 / 1306216 | 54275 / 55541 | 872.2 / 781.2 |

این اعداد microbenchmark محلی‌اند، نه تضمین latency شبکه یا بهبود سرعت مسیر.
افزایش فیلدها query جدیدی ندارد؛ HIT کش هفته همچنان بدون query است.

نتیجهٔ بررسی این تغییر:

- build فرانت و ۲۲۸ تست فرانت پاس شدند.
- ۸۷ تست بکندِ شاخص‌ها، hazard، assets، ETag/کش، باد و جداسازی/انتشار استیج و
  production، و ۱۴ تست دیگر بستهٔ هفته پاس شدند.
- هر ۱۶ ترکیب مرورگر، عرض ۳۲۰/۳۶۰ و حفظ اسکرول پاس شد؛ فقط یک GET هوا در هر
  ورود و صفر GET اضافه برای تغییر تم/بازه ثبت شد. DOM تمام نمودارهای قبلی با
  مین مرجع مقایسه شد؛ فقط جایگاه تأییدشدهٔ کمینه/بیشینه تغییر دارد.

دو شکست قبلی suite هفته با کد دست‌نخوردهٔ مین نیز بازتولید شدند و مربوط به
این شاخص‌ها نیستند: `test_route_descent_applies_only_matching_canonical_chain`
هنوز فرود شهرستانک را null انتظار دارد، در حالی که fixture فعلی ۳۲ متر دارد؛
`test_reapplying_unchanged_descent_preserves_weather_revision` نیز هنگام بازاعمال
شواهد فرود/فاصله، revision کش را عوض می‌کند. این دو تست در شمار ۱۴ پاس بالا
نیستند. در این تغییر، منطق و دادهٔ مسیرها برای رفع مستقل آن‌ها دست‌کاری نشده‌اند؛
بنابراین ادعای سبزبودن کل suite بکند نداریم.
