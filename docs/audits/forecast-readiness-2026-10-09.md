# بررسی آمادگی انتقال پیش‌بینی هفته به main — ۹ اکتبر ۲۰۲۶

بررسی مستقیم دیتابیس‌های استیج و پروداکشن در transaction فقط‌خواندنی انجام شد؛
هیچ import، migration، دریافت از provider یا deploy اجرا نشد. این یک snapshot است؛
پوشش هوا با اجرای scheduler تغییر می‌کند. شمارش نقاط شامل نقاط میانی مسیر است؛
نداشتن مسیر برای مقصد point-only نقص محسوب نمی‌شود.

ناقص‌بودن هفته به معنی نبود همهٔ اطلاعات آن نقطه نیست.

## پیش‌نیازهای انتشار

- پروداکشن فعلاً با افق provider برابر ۷ روز کار می‌کند؛ هیچ نقطه‌ای پوشش
  ۱۹۲ ساعت ندارد. برای شروع در هشت روز و رسیدن احتمالی روز بعد، افق دریافت
  ۱۰ روز مثل استیج لازم است. compose پیش‌فرض ۷ دارد و deploy.sh نیز ۷ را
  صریحاً می‌نویسد؛ انتقال کد به‌تنهایی این تنظیم را اصلاح نمی‌کند.
- cache واقعی پروداکشن LocMemCache است. Redis مشترک باید در تنظیمات و سرویس
  دیپلوی پروداکشن فعال شود؛ صرف وجود تعریف سرویس Redis کافی نیست.
- پروداکشن هنوز schema قدیمی مسیر را دارد؛ صفر بودن شمارش فرود/فاصله در
  snapshot پروداکشن به معنی فرود صفر یا حذف داده نیست. migration و اعمال
  fixture مشتق‌شدهٔ مسیر با command مربوط لازم است. deploy پروداکشن فعلی
  این command را اجرا نمی‌کند. پس از دریافت داده، cache هفته باید گرم و
  صفحات مقصد/مسیر دوباره بررسی شوند.
- دادهٔ UV در snapshot پروداکشن موجود نیست؛ ingest نسخهٔ جدید و پرشدن این
  فیلد پیش از اتکا به قواعد تجهیزات UV باید بررسی شود.
- main محلی commit جدید حوض سلطان دارد که stage ندارد؛ هنگام ادغام باید
  حفظ شود. merge-tree فعلی main/stage بدون conflict است، ولی merge انجام
  نشده. نقطهٔ اضافهٔ پروداکشن نسبت به استیج: hoz-soltan.

اطلاعات ناشناخته نباید با عدد ساختگی پر شوند. برای اعلام «تمام مسیرها کامل
هستند» هنوز تکمیل داده لازم است؛ انتشار با نمایش وضعیت نامشخص تصمیم محصول است.
