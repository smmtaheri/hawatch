# خروج و همگام‌سازی تب‌های هواچ

نشست Django در سرور مرجع ورود و دسترسی است. سایت و پنل ادمین دو نشست مستقل
در همان دیتابیس دارند؛ ورود ادمین، حساب سایت را فعال نمی‌کند. خروج موفق با
`POST auth/logout/` نشست سایت در همان مرورگر را باطل می‌کند؛ ادمین، دستگاه‌ها
و مرورگرهای دیگر وارد باقی می‌مانند. خروج از ادمین هم فقط نشست ادمین را باطل می‌کند.
مدت پیش‌فرض نشست ۳۰ روز است و بستن مرورگر آن را پایان نمی‌دهد.

فرانت بعد از موفقیت درخواست خروج، پیام `logout` را با BroadcastChannel و
رویداد storage به تب‌های **همان origin** می‌فرستد. پیام فقط action و nonce دارد؛
شماره، طرح، cookie یا credential در localStorage ذخیره نمی‌شود. دریافت پیام
فوراً حساب را خالی، پاسخ‌های در حال اجرای قدیمی حساب را بی‌اعتبار و کش بسته‌های
پیش‌بینی وابسته به حساب را پاک می‌کند؛ دسترسی روزها از API دوباره خوانده می‌شود.
پیام مشترک دو کانال فقط یک بار پردازش می‌شود و دوباره منتشر نمی‌شود.

ورود موفق نیز به تب‌های دیگر خبر داده می‌شود تا نشست و مجوزها را از سرور بخوانند.
در بازگشت focus، visible شدن تب و بازگشت از Back/Forward cache، حساب با درخواست
no-store بررسی می‌شود. تغییر وضعیت احراز هویت، دسترسی هواشناسی را هم تازه می‌کند.
پاسخ دیررس پیش از خروج اجازهٔ برگرداندن حساب را ندارد. شکست خروج، خروج موفق
اعلام نمی‌کند؛ شکست موقت بررسی حساب نیز وضعیت قبلاً تأییدشده را به‌اشتباه تغییر نمی‌دهد.

BroadcastChannel در صورت مسدودی storage کار می‌کند؛ storage در نبود کانال
جایگزین است. اگر هر دو توسط مرورگر مسدود باشند، بررسی هنگام بازگشت به تب
جایگزین همگام‌سازی فوری می‌شود. مرورگر تب منجمد را تا ازسرگیری اجرا نمی‌کند؛
مجوز واقعی سرور از زمان موفقیت خروج باطل شده است. دامنهٔ www، دامنهٔ اصلی،
پورت استیج و پنجرهٔ خصوصی origin/storage مستقل دارند؛ انتظار همگام‌سازی بین
این‌ها یا دستگاه‌های دیگر وجود ندارد.

این تغییر endpoint ورود، OTP، مدت نشست یا ظاهر موبایل/دسکتاپ را عوض نمی‌کند.
APIهای auth همچنان باید در CDN از cache عمومی مستثنا باشند.


## جداسازی سایت و ادمین

سایت از `hawatch_site_session` و `hawatch_site_csrf` در مسیر `/` استفاده می‌کند.
ادمین از `hawatch_admin_session` و `hawatch_admin_csrf` در مسیر `/admin/` استفاده
می‌کند. کوکی CSRF مستقل است تا ورود یکی، فرم باز دیگری را با چرخش token خراب نکند.
استیج همین چهار کوکی را با پیشوند `hawatch_qa_` دارد. تنظیم‌های Secure، HttpOnly،
SameSite و انقضا همان تنظیم‌های Django هستند.

`AdminCookieIsolationMiddleware` پیش از middleware نشست قرار دارد و فقط برای
`/admin` و `/admin/…` کوکی‌های request/response را تطبیق می‌دهد؛ settings سراسری
را تغییر نمی‌دهد. ادمین هیچ fallback به کوکی سایت ندارد. سرویس یا migration جدید
لازم نیست و Redis/کش هوا تغییری نمی‌کند.

پس از اولین دیپلوی این جداسازی، سایت و ادمین یک‌بار ورود مجدد می‌خواهند؛ کوکی‌های
مشترک قدیمی `sessionid` و `csrftoken` نادیده گرفته می‌شوند. آن‌ها به نشست جدید
منتقل نمی‌شوند، چون نمی‌توان ورود قبلی ادمین را از ورود صریح سایت تشخیص داد.

اعتبارسنجی جداسازی: ۲۶ تست API و ۷ تست ورود/همگام‌سازی فرانت پاس شدند.
Chromium در عرض‌های ۳۹۰ و ۱۴۴۰ با یک cookie jar و چند تب، ورود مستقل ادمین،
خروج سایت و تب دوم، حفظ ورود ادمین، و خروج ادمین بدون خروج سایت را با API
واقعی محلی و دیتابیس تست مستقل تأیید کرد. سرور production تغییر نکرد.
