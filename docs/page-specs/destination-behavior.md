# رفتار Destination

## ورودی

`destinationSlug` باید از catalog resolve شود. نمونهٔ اصلی `/destination/tochal` است. بدون مقصد معتبر، not-found با مسیر Home نمایش داده شود.

## کنترل‌های forecast

- انتخاب روز، date context را تغییر می‌دهد.
- انتخاب مسیر، route recommendation یا navigation به Route را تغییر می‌دهد.
- انتخاب نیمه‌شب/صبح/ظهر/شب، hourly و route weather را هماهنگ تغییر می‌دهد.
- بازهٔ کاملاً گذشته نسبت به `meta.current_local_time` در `Asia/Tehran` کم‌رنگ است؛ بازهٔ انتخاب‌شده همچنان خوانا می‌ماند.
- بدون query صریح، API بر اساس ساعت تهران `date` و `period` پیش‌فرض برمی‌گرداند.
- پنجره‌ها ثابت و غیرهم‌پوشان‌اند: نیمه‌شب ۰۰–۰۶، صبح ۰۶–۱۲، ظهر ۱۲–۱۸ و شب ۱۸–۲۴؛ هر پنجره سه برش دوساعته دارد.
- stale باید با هشدار قابل فهم نمایش داده شود؛ timestamp خام ISO و عبارت «آخرین به‌روزرسانی: ...» در UI نمایش داده نمی‌شود.

## محتوای انتخاب روز

- بالای day tabs فقط label «انتخاب روز» نمایش داده می‌شود.
- heading و توضیح تکراری «پیش‌بینی ... / روز و ساعت را انتخاب کن...» حذف می‌شوند.

## قالب مشترک

Destination و Point هر دو از `PlaceForecastPage` استفاده می‌کنند. baseline بصری همان screenshotهای Destination است. جزئیات: [design/pages/place-forecast.md](../../design/pages/place-forecast.md).

## layout mobile

روزها قبل از کنترل هوا قرار می‌گیرند. در موبایل دو مسیر برتر قبل از کنترل روز/هوا نمایش داده می‌شوند و مسیرهای باقی‌مانده از طریق bottom sheet انتخاب می‌شوند. route card تنها نام مسیر و دو fact جداگانهٔ «ارتفاع‌گیری» و «مسافت» دارد؛ `trail_label` و `origin` زیر نام تکرار نمی‌شوند. در کارت «جزئیات تخصصی» فقط دو metric اول inline هستند؛ دکمهٔ «دیدن همهٔ جزئیات تخصصی {روز}» sheet نیم‌صفحهٔ قابل‌بستن با backdrop، Escape و swipe-down را باز می‌کند و همهٔ metricها را نمایش می‌دهد. برای فهرست مسیرهای بیشتر، trigger «دیدن همهٔ مسیرها» sheet مسیرها را باز می‌کند. جمع‌بندی هواچ در mobile بعد از کارت جزئیات تخصصی قرار دارد. عنوان «انتخاب روز» و کنترل سه‌دکمه‌ای «بازهٔ نمایش هوا» در یک ردیف (به‌ترتیب RTL: روز در راست، بازه در چپ) هستند و day tabs زیر آن می‌آیند. کارت ساعتی جاری هنگام ورود یا تغییر context به‌صورت خودکار در viewport قرار می‌گیرد. هیچ card یا grid نباید root را عریض‌تر کند.

## خطا و داده ناقص

اگر forecast provider بخشی از داده را ندهد، مقدار موجود با timestamp نمایش داده شود و fieldهای ناقص `در دسترس نیست` یا معادل مشخص داشته باشند. از پرکردن silently با صفر خودداری شود.
