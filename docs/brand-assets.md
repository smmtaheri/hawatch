# دارایی‌های برند هواچ

## لوگوی محصول

منبع هندسهٔ لوگوی فعلی، SVG خطی ابر و کوه در
`apps/web/src/components/brandMark.svg` است. Header و تصویر خلاصهٔ مسیر همین
فایل را با `currentColor` و رنگ accent هر تم مصرف می‌کنند.

نسخه‌های عمومی و آیکون‌های مشتق‌شده در `apps/web/public/brand/v2/` قرار دارند:

- `logo-dark.svg` با رنگ `#32e0e0` برای سطح تیره و `logo-light.svg` با رنگ
  `#007c8b` برای سطح روشن؛ HTML اولیهٔ SSR با `html[data-theme]` نسخهٔ مناسب را
  نمایش می‌دهد، پس هنگام اجرای React شکل لوگو عوض نمی‌شود.
- `favicon.svg` با رنگ متناسب با تم مرورگر، و PNGهای ۱۶/۳۲/۴۸ و `favicon.ico`
  برای مرورگرهای دیگر.
- `apple-touch-icon.png` و `pwa-192.png` / `pwa-512.png` برای میانبر و نصب؛
  `pwa-maskable-512.png` نشان را داخل محدودهٔ امن maskable نگه می‌دارد.
- `site.webmanifest` به آیکون‌های همان پوشه ارجاع دارد.
- `social-share-1200x630.png` تصویر پیش‌فرض Open Graph و Twitter است.

HTML اولیه و entry فرانت به مسیرهای نسخه‌دار `/brand/v2/...` اشاره دارند تا
کش لوگو و آیکون‌های قبلی دوباره نمایش داده نشود. فایل‌های اصلی قدیمی در
`public/brand/` و تصاویر مرجع حفظ شده‌اند و در HTML فعلی استفاده نمی‌شوند.

بازسازی دارایی‌ها از منبع SVG، بدون تغییر تصاویر اصلی:

```bash
python3 scripts/generate_brand_assets.py
```

این فرمان محلی به Pillow و ImageMagick (`convert`) نیاز دارد؛ در build یا deploy
اجرا نمی‌شود. برای تغییر هندسهٔ لوگو، Header و تصویر اشتراک‌گذاری از منبع SVG
استفاده می‌کنند و دارایی‌های عمومی با همین فرمان بازسازی می‌شوند. فایل
`public/new-design/brand-mark.svg` نسخهٔ اصلی بستهٔ طراحی است و حفظ می‌شود.

## آیکون‌های تخصصی هوا

هشت آیکون تخصصی weather در `apps/web/public/icons/specialist/` نگهداری می‌شوند. فایل canonical برای UI، `hawatch-specialist-icons.svg` است و `SpecialistMetricIcon` از symbolهای آن با `currentColor` استفاده می‌کند؛ SVGهای تک‌آیکون فقط fallback یا استفادهٔ مستقیم‌اند. اندازهٔ پایه ۲۴px و اندازهٔ کارت متریک ۲۸px است. source pack موقت یا preview آن نباید در ریشهٔ پروژه نگهداری یا به runtime اضافه شود.

## آیکون نوع نقطه

`Point.category_key` کلید معنایی آیکون نقطه است و از دیتابیس/کاتالوگ
خوانده می‌شود؛ بنابراین برای ثبت نقطه جدید، آیکون را با همین فیلد انتخاب کنید
و نیازی به تغییر کد یا deploy برای هر رکورد جدید نیست. کلیدهای فعلی عبارت‌اند
از `mountain`، `ridge`، `volcano`، `waterfall`، `meadow`، `forest`، `desert`،
`lake`، `beach`، `city`، `village` و `neighborhood`. کلید `city` از glyph بافت
شهری، کلید `neighborhood` از glyph محلهٔ کم‌تراکم و کلید `village` از glyph خانهٔ
روستایی استفاده می‌کند تا شهر، محله و روستا با هم اشتباه نشوند. هر شهر باید با
`place_type: "city"` و `category_key: "city"` ثبت شود و هر محلهٔ شهری با
`place_type: "neighborhood"` و `category_key: "neighborhood"`. کلید `ridge` برای
ارتفاعات و خط‌الرأس به‌صورت بصری در خانوادهٔ
کوه نمایش داده می‌شود تا ارتفاعات گوگلی و مقصدهای هم‌معنا از قله‌ها جدا و
گمراه‌کننده نشوند؛ `beach` نیز آیکون ساحل مستقل دارد.

برای نمونه، نقطه آبشار باید `category_key: "waterfall"` داشته باشد. اگر کلیدی
خارج از فهرست ثبت شود، UI عمداً یک نشان خنثی نمایش می‌دهد و آن را به‌اشتباه
کوه نشان نمی‌دهد. افزودن یک شکل کاملاً جدید به این مجموعه یک تغییر محصولی است
و فقط برای خودِ آیکون جدید به deploy نیاز دارد؛ انتخاب آیکون‌های موجود همچنان
کاملاً database-first است.

اگر یک ردیف قدیمی یا یک مقصد ثانویه در `weather_points`، `category_key` را
تکرار نکرده باشد، API آن را از `place_type` شناخته‌شده (مثلاً `lake` → `lake`)
به‌صورت مرکزی کامل می‌کند؛ import کاتالوگ نیز همین resolution را ذخیره می‌کند.
به این ترتیب مقصدهایی مثل دریاچهٔ قوچ‌گلی هیچ‌وقت به نشان خنثی برنمی‌گردند.

## تصویر دستهٔ مقصد

برای دسته‌های `waterfall`، `desert`، `meadow`، `beach`، `city`، `village` و `neighborhood`، آرت‌ورک‌های بدون
متن در `apps/web/public/images/destination-artwork/` نگهداری می‌شوند. این
فایل‌ها در UI به‌صورت mask و با توکن `--teal` رنگ می‌گیرند تا در هر دو تم با
سیستم طراحی یکدست بمانند. نام دسته یا هر کپشن دیگری نباید داخل خود تصویر تکرار
شود؛ نام و اطلاعات مقصد از متن واقعی کارت خوانده می‌شود.
