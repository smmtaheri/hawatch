# بررسی کاهش ارتفاع و زمان‌بندی مسیرها — ۹ اکتبر ۲۰۲۶

کاهش ارتفاع (`descent_m`) مجموع پایین‌رفتن در همان مسیر ثبت‌شدهٔ مبدأ → مقصد است؛ نه ترک برگشت و نه اختلاف ارتفاع دو سر مسیر. دادهٔ ۳۴ مسیر پس از بررسی ترک محلی و تطبیق زنجیرهٔ واقعی دیتابیس در production ثبت شد. اکنون ۱۵۲ مسیر مقدار دارند و ۸۷ مسیر همچنان نامشخص‌اند. صفر با نامشخص متفاوت است.

## روش و محدودهٔ تغییر

- فقط مقدار کاهش ارتفاع و provenance تغییر کردند؛ افزایش ارتفاع، طول ثبت‌شده، زمان‌بندی، RoutePointها و مختصات دست‌نخورده‌اند.
- برش یک‌طرفه تا اولین رسیدن به مقصد؛ برگشت و دسترسی خارج از برش ثبت‌شده محاسبه نشده‌اند. بخش‌های معرفی‌شدهٔ `route_sections` و جهت معکوس صریح پشتیبانی می‌شوند.
- لینک ترک از `route_slug`/`route`، `filename`/`file`، منبع ثبت‌شده یا `evidence_tracks` کاتالوگ خوانده می‌شود. نام قدیمی پژوهش URL عمومی را عوض نمی‌کند.
- کنترل مبدأ و مقصد حداکثر ۱۰۰ متر، نقطهٔ میانی حداکثر ۵۰۰ متر و پرش نمونه حداکثر ۳۰۰ متر حفظ شد. طول برش با طول ثبت‌شده مقایسه شد؛ اختلاف بیش از ۲۵٪ یا ۵۰۰ متر، هرکدام بزرگ‌تر، متوقف شد.
- پروفایل ارتفاع هر ۵۰ متر نمونه‌برداری و با میانگین ۵ نمونه نرم می‌شود. مجموع کاهش از همان پروفایل به دست می‌آید. ارتفاع دستگاه صرفاً مبنای تخمین پروفایل است و ارتفاع canonical نقاط/DEM تغییر نمی‌کند.
- GPX و manifest روی local ماندند. دریافت هوا، deploy، تغییر زمان و restart سرویس اجرا نشد. قبل از write بک‌آپ دیتابیس گرفته شد.

ابزار بررسی آفلاین: `scripts/review-route-reductions.py`؛ ورودی `--registered-routes` snapshot فقط‌خواندنیِ زنجیرهٔ واقعی مسیرهاست. مثال:

```bash
python3 scripts/review-route-reductions.py \
  --source-root "$PWD" \
  --registered-routes /tmp/hawatch-route-live-current.json \
  > /tmp/route-reductions-review.json
```

خروجی ابزار به‌تنهایی مجوز نوشتن نیست؛ پروفایل، منبع، جهت و برنامهٔ تغییر بازبینی می‌شوند. فقط `slug`، `chain`، `descent_m` و `evidence` موارد پذیرفته‌شده به fixture مشتق‌شده اضافه شدند. دادهٔ جدید در `apps/api/fixtures/route_descent_v1.json` حفظ شده تا deploy بعدی آن را بازتولید کند؛ ابزار قدیمی `derive-route-descent.py` همچنان baseline مستقل ۱۱۸ پروفایل قبلی است.
