# توکن و قرارداد تایپوگرافی هواچ

این سند قرارداد مشترک تایپوگرافی برای Home، Point، Route و Login است. فونت بخشی از هویت محصول است و نباید برای صفحه‌ای جداگانه با فونت دیگری override شود.

## فونت و بارگذاری

- فونت اصلی: Estedad Variable، مناسب متن فارسی و لاتین، با محور وزن `100–900`.
- فایل runtime: `apps/web/public/fonts/estedad-variable.woff2`.
- مجوز: `apps/web/public/fonts/OFL.txt`؛ هر دو فایل باید در repository بمانند.
- تعریف واحد `@font-face` در `apps/web/src/styles/tokens.css` است و HTML فونت را preload می‌کند.
- stack رسمی: `"Estedad", "Noto Sans Arabic", Tahoma, Arial, sans-serif`.
- body، heading، button، input، select، textarea، tab و componentهای سفارشی باید از همین stack ارث ببرند.
- `font-display: swap` الزامی است تا متن هنگام بارگذاری فونت ناپدید نشود.

## سلسله‌مراتب و scale

مقدارهای runtime در `apps/web/src/styles/tokens.css` و مقدارهای canonical در `design/tokens/visual-tokens.json` نگهداری می‌شوند.

| متن بدنه | ۱۶px | ۱۶px | ۱٫۷ | ۴۰۰ |
| metadata و واحد | ۱۳–۱۴px | ۱۳px | ۱٫۵ | ۴۰۰ |
| label و کنترل | ۱۳–۱۵px | ۱۳px | ۱٫۴۵ | ۵۰۰ |

ترتیب اهمیت اطلاعات همان ترتیب محصول است: وضعیت فعلی، تغییر مهم، انتخاب روز/بازه، پیش‌بینی ساعتی، جزئیات تخصصی. از `<strong>` به‌تنهایی برای ساختن سلسله‌مراتب استفاده نشود؛ عنوان‌ها باید semantic (`h1`/`h2`/`h3`) باقی بمانند و وزن فقط نقش بصری را کامل کند.

## قواعد فارسی، عدد و واحد

- `letter-spacing` برای متن فارسی `normal` است؛ negative tracking، به‌خصوص روی عنوان‌ها، ممنوع است.
- برای چیدمان از فاصلهٔ کامل یا `&nbsp;` استفاده نشود؛ فاصله باید با CSS کنترل شود. متن محصول بازنویسی نمی‌شود مگر در scope همان feature.
- عدد و واحد در متن ترکیبی با `bdi` یا `unicode-bidi: isolate` از جریان RTL جدا می‌شوند.
- مقادیر عددی از `font-variant-numeric: tabular-nums` استفاده می‌کنند تا ستون‌ها و کارت‌های ساعتی هم‌تراز بمانند.
- واحد کوچک‌تر از مقدار اصلی است، اما نباید به‌قدری کوچک یا کم‌رنگ شود که خوانایی از بین برود.

## theme و دسترسی‌پذیری

- این قرارداد در light و dark یکسان است؛ رنگ متن و muted باید در هر دو theme حداقل کنتراست WCAG AA متن عادی را حفظ کند.
- وضعیت‌های normal/change/critical فقط با رنگ منتقل نمی‌شوند و متن یا نشانهٔ بصری هم دارند.
- هیچ کنترل فارسی تعاملی نباید به‌صورت پیش‌فرض زیر ۱۳px رندر شود.
- تغییر فونت نباید root را عریض کند یا scroll افقی صفحه ایجاد کند؛ overflow مجاز فقط در containerهای مشخص خودشان است.

## QA

بعد از هر تغییر تایپوگرافی، این موارد باید بررسی شوند:

1. همهٔ صفحه‌ها در light/dark و mobile/desktop با Estedad رندر شوند.
2. عنوان‌های فارسی شکسته، اعداد، واحدهای `km/h`، دما، ارتفاع و زمان خوانا و جدا از جریان RTL باشند.
3. focus، keyboard order، overflow و کنتراست در هر چهار ترکیب بررسی شود.
4. `npm run build`، تست‌های frontend و `git diff --check` اجرا شوند؛ live font فقط بعد از deploy دوباره با computed style تأیید می‌شود.
