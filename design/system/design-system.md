# سیستم طراحی هواچ

## هدف

سیستم طراحی هواچ برای تجربه‌ای آرام، طبیعی، خلوت، قابل‌اعتماد و تصمیم‌محور ساخته شده است. صفحه باید به کاربر کمک کند بفهمد «الان چه خبر است؟»، «چه تغییری مهم است؟» و «با این شرایط چه تصمیمی بگیرم؟».

## قراردادهای ثابت

- زبان فارسی، RTL و فونت self-hosted و متغیر Estedad؛ جزئیات scale و قواعد عدد/واحد در [راهنمای typography](../tokens/typography.md) است.
- رنگ هویت teal؛ amber برای تغییر مهم؛ coral برای وضعیت حساس.
- light سفید اداری و dark مشکی کامل نیستند.
- کارت‌ها سطح‌های لایه‌لایه، border ظریف، radius حدود ۱۶ تا ۲۲px و shadow نرم دارند.
- لوگو از wordmark رسمی «هواچ» و mark شامل دو خط صعودی و سه نقطه تشکیل شده است؛ assetهای runtime در `apps/web/public/brand/` نگهداری می‌شوند و نسخهٔ light/dark متناسب با پس‌زمینه جابه‌جا می‌شود.
- تصویر hero بخشی از لحن محصول است؛ overlay باید متن و action را خوانا نگه دارد.

## الگوی صفحه

۱. shell و header کوچک با برند، theme toggle و ورود.
۲. hero یا page header برای context و تصمیم اصلی.
۳. محتوای اصلی در card surfaceهای مجزا.
۴. وضعیت‌ها و هشدارها کنار دادهٔ مربوط، نه در انتهای نامرتبط صفحه.
۵. footer سبک با tagline «هوای نقطه، برنامهٔ مسیر».

## الگوی دادهٔ هوا

داده با hierarchy ثابت ارائه می‌شود: وضعیت فعلی، تغییر مهم، انتخاب روز/بازه، پیش‌بینی ساعتی، سپس جزئیات تخصصی. در Route همین منطق روی محور نقاط مسیر تکرار می‌شود تا کاربر بتواند تصمیم را بر اساس زمان و مکان بگیرد.

## دسترسی‌پذیری

- کنترل‌ها label قابل فهم و focus قابل مشاهده داشته باشند.
- وضعیت با متن و icon نیز بیان شود.
- ترتیب DOM و tab order با RTL و ترتیب تصمیم هم‌خوان باشد.
- target تعاملی برای touch به‌اندازهٔ کافی بزرگ بماند.
- روی تصویر hero، متن در هر دو theme کنتراست کافی داشته باشد.
